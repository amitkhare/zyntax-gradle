Jansi Android aarch64 source port, 2026 Zyntax contributors.

This component assembles original Jansi 1.18, Jansi Native 1.8 and HawtJNI runtime
1.17 Java sources with JNI generated by the upstream HawtJNI 1.17 generator.
SOURCE-PROVENANCE.properties records the exact upstream commits and tool hash.
No prebuilt Jansi or HawtJNI runtime classes or native binaries are repackaged.

Changes: HawtJNI Library declares the Android aarch64 build identity and rejects
incompatible JVM OS/architecture/bitness. An explicit library.jansi.path is
authoritative. Default extraction selects only the Android aarch64 resource and
the JVM temporary directory. Native permissions use Java NIO without a child
process. Loading failure propagates; no system library or other platform search
is performed. Original extraction strategies and optional version naming remain.

The Jansi Native Termios model retains Bionic's line-discipline byte and uses
POSIX cfgetispeed/cfsetispeed/cfgetospeed/cfsetospeed accessors, because Android
encodes those speeds in its flags rather than glibc's struct members. All JNI is
regenerated from these declarations against NDK r29's real Android headers.
Jansi Native 1.8 originally used generator 1.16; the Android port uses 1.17,
matching the bundled runtime, to support its non-member POSIX field accessors.
The upstream HawtJNI C runtime helper is compiled directly from its source tree
with AttachCurrentThread's JNIEnv** argument matching Android's JNI header.
Generated JNI bindings are not hand-edited.

Jansi and Jansi Native are Apache-2.0. HawtJNI's root license.txt is Apache-2.0;
individual HawtJNI runtime/generated-native files retain their upstream EPL-1.0
headers and notices. Both license texts and HawtJNI's original notice.md are
included. The sources JAR includes the corresponding modified Java/native source
and these recipes. NDK notices are retained for the target runtime/toolchain.

This is an Android-only component, not universal Bionic detection or a claim of
complete Gradle compatibility. Host checks inspect Java/resource/ELF structure.
Android JNI execution must be verified separately before distribution use.
